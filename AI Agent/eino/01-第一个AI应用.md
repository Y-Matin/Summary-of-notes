# 第一个 AI 应用

## 目标

这一章的目标是跑通最小 AI 对话程序，理解 Eino 中 `ChatModel` 和 `schema.Message` 的基本使用方式。

大模型应用最常见的入口就是对话：用户提出问题，程序把系统规则和用户问题组织成消息，交给模型生成回答。Eino 的入门案例就是从这个最小闭环开始，先不引入工具、知识库和复杂编排，只关注“如何把一次对话请求送进模型并拿到结果”。

这一章要建立的直觉是：AI 应用的第一层抽象不是 HTTP 接口，也不是页面聊天框，而是 `messages -> model -> response` 这条链路。后续所有 ChatTemplate、ToolsNode、Agent、Graph，本质上都是围绕这条链路增强能力。

## 环境准备

### Go

教程使用 Go 1.24.x。实际学习时建议使用较新的 Go 版本，避免依赖安装和泛型相关问题。

```bash
go version
```

### Ollama

Ollama 用于在本地运行大语言模型。

```bash
ollama list
ollama pull modelscope.cn/Qwen/Qwen3-32B-GGUF:latest
```

如果本机配置不足，可以换更小的 Qwen3 模型。

本地模型的优点是开发方便、成本低、数据不出本机；缺点是模型效果和速度受机器配置影响。学习阶段用本地模型可以更专注于 Eino 代码结构。

### 阿里云百炼

如果不方便本地部署 Ollama，可以使用兼容 OpenAI 接口的在线模型服务。教程中使用阿里云百炼的兼容模式。

在线模型的优点是部署简单、效果稳定；缺点是需要 API Key，并且要考虑调用费用、网络和数据合规。

## 核心概念

### ChatModel

`ChatModel` 是大模型调用组件。它负责把消息列表发送给模型，并返回模型生成的消息。

常见调用方式：

- `Generate(ctx, messages)`：一次性返回完整回复。
- `Stream(ctx, messages)`：流式返回增量片段。

### Message

`schema.Message` 表示一次对话消息。常用角色：

- `schema.SystemMessage(...)`：系统提示词，用来设定角色、规则和约束。
- `schema.UserMessage(...)`：用户输入。
- `schema.AssistantMessage(...)`：模型回复，常用于对话历史。

## 基本流程

```text
创建 context
  -> 初始化 ChatModel
  -> 构造 messages
  -> 调用 Generate 或 Stream
  -> 输出模型回复
```

## 核心代码：Ollama 直接回复

```go
ctx := context.Background()

model, err := ollama.NewChatModel(ctx, &ollama.ChatModelConfig{
    BaseURL: "http://127.0.0.1:11434",
    Model:   "modelscope.cn/Qwen/Qwen3-32B-GGUF:latest",
})
if err != nil {
    panic(err)
}

messages := []*schema.Message{
    schema.SystemMessage("你是一个乐于助人的助手"),
    schema.UserMessage("请介绍一下 Go 语言的特点"),
}

resp, err := model.Generate(ctx, messages)
if err != nil {
    panic(err)
}

fmt.Println(resp.Content)
```

## 核心代码：流式对话

```go
stream, err := model.Stream(ctx, messages)
if err != nil {
    panic(err)
}
defer stream.Close()

for {
    chunk, err := stream.Recv()
    if err != nil {
        break
    }
    fmt.Print(chunk.Content)
}
```

流式输出适合聊天界面、命令行逐字输出、长文本生成等场景。

## 核心代码：阿里百炼兼容 OpenAI 接口

```go
model, err := openai.NewChatModel(ctx, &openai.ChatModelConfig{
    BaseURL: "https://dashscope.aliyuncs.com/compatible-mode/v1",
    Model:   "qwen3-32b",
    APIKey:  "your api key",
})
```

模型调用逻辑与 Ollama 基本一致，只是 `ChatModel` 的实现和配置不同。

## 记忆点

- Eino 把模型调用统一抽象成 `ChatModel`。
- 输入输出围绕 `schema.Message` 展开。
- `SystemMessage` 负责约束模型行为，`UserMessage` 负责表达用户任务。
- `Generate` 简单直接，`Stream` 更适合交互式体验。
- 本地模型和云模型的差异主要在初始化配置，业务代码可以尽量保持一致。
