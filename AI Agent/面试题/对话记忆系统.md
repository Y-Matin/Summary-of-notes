# 对话记忆系统

## 作用
- 每次对话先检索相关记忆，再注入 Prompt，回答结束后异步抽取新的记忆并保存。




## 短期记忆

### 影响范围
- 短期记忆负责当前对话上下文
- 例如：
  ```
  用户：我叫张三
  助手：你好，张三
  用户：我喜欢 Go 语言
  ```

### 负责解决的问题：
1. 当前对话能连续进行；
2. 模型能看到前面的上下文；
3. 控制上下文长度，避免无限增长。 

- 短期记忆通常与 conversation_id 或 session_id 绑定。

### 流程图
这条链路强调低延迟，必须尽快完成
```
用户问题
  ↓
读取短期上下文
  ↓
检索长期记忆
  ↓
拼接 Prompt
  ↓
LLM 回答
  ↓
返回用户
```
- 

## 长期记忆
- 长期记忆负责从历史对话中提炼用户信息
- 例如
  ```
  用户姓名：张三
  技术偏好：Go
  职业方向：后端开发
  正在进行的项目：Agent 平台
  ```
### 负责解决的问题
- 用户换一个会话后仍然“认识”用户；
- 不必保存所有原始聊天记录；
- 只保留对未来有帮助的事实、偏好和任务信息。

### 生成逻辑
这条链路可以异步执行，不应该阻塞用户看到回答。
```
对话结束
  ↓
抽取有价值信息
  ↓
判断新增/修改/删除
  ↓
保存长期记忆
```
